Positioning and comparison

ArcLM occupies a narrow, honest niche: a readable local toolkit for learning and light application work around language models, with optional heavy compute. The comparisons below are qualitative, based on architecture — not benchmark claims.

vs using Hugging Face only

  • Use HF when: you need the Hub, production tokenizers, or ecosystem integrations as the main product.
  • Add ArcLM when: you want a light local layer, data/agent/security tools, or a tiny model to study alongside HF.
  • Do not claim: ArcLM is faster or “better” than transformers.

vs large training frameworks

  • Use large frameworks when: multi-node training, serving, or mature distributed optimizers are requirements.
  • Use ArcLM when: single-machine education, prototypes, embedded agents, or constrained environments.

What is verified vs aspirational

  • Verified: light install, tokenizer/data/security/agent examples, tiny native train smoke, tiny-gpt2 HF load on CPU, CI light+torch jobs, Blocks builder checks, PyPI 2.0.0.
  • Experimental: multi-GPU distributed contracts, QLoRA paths needing bitsandbytes.
  • Aspirational: broader retrieval/RAG components, richer Arabic examples (see roadmap — labeled Proposed/Planned as appropriate).
