Limitations and current status

Status as of ArcLM 2.0.0 on PyPI, branch cleanup-2.0. Development Status classifier: 4 – Beta.

What works today (verified)

  • Core install without torch (NumPy + SentencePiece).
  • Word + SentencePiece tokenizers; dataset load/validate/dedupe.
  • Security redaction, path safety, status; full crypto with [security].
  • Agent tools + deterministic runner examples (no GPU).
  • Native ArcLM forward pass; tiny pretraining smoke on CPU.
  • HF load_any_model + predict/chat on sshleifer/tiny-gpt2 (CPU).
  • Training run tracking with path redaction.
  • CLI (14+ commands); doctor without torch.
  • Blocks builder: 7 editions, check-drift/test-all green when last run.
  • Examples suite run-verified: 28/28 CPU-local (session result).
  • CI: light + torch matrices on Python 3.9–3.14 (after UTC fix).
  • PyPI package arclm 2.0.0 published.

Experimental

  • arclm.distributed — DDP/FSDP contracts and validation; not a production multi-node trainer.
  • QLoRA runtime — depends on bitsandbytes and hardware; not fully exercised in default CI.
  • Web Studio training jobs — implemented but heavier; torch required.

Incomplete or thin

  • No first-class retrieval / RAG / vector index module (search = hyperparameter search only).
  • Arabic-specific NLP examples and chat-template tests for instruct models: not fully verified.
  • Next.js Studio frontend: present but not fully documented on this site.
  • Extended root modules (workflow.py, config_schema.py, …) have uneven docs coverage.

Unsupported

  • Production multi-node training/serving as a product goal.
  • Guaranteed compatibility with every Hugging Face Hub model.
  • Native model quality comparable to commercial chat LLMs.
  • Co-installing multiple Blocks side by side (they all provide arclm).

Areas needing more testing

  • Instruction-tuned chat models with real chat_template (beyond tiny-gpt2).
  • Longer SFT runs and LoRA merge quality metrics.
  • Studio frontend ↔ backend contract tests under load.
  • Windows path edge cases in tracking (partially covered locally).

When another tool is more appropriate

  • Large-scale distributed training → dedicated frameworks.
  • Managed LLM APIs as the product → use provider SDKs; ArcLM agents can still orchestrate tools.
  • Production RAG at scale → dedicated vector DBs and retrieval stacks.
