Data and tokenizers core

Datasets

What: load local records, validate fields, remove exact duplicates, chain cleaning steps. Why: dirty data wastes training time and skews metrics. Modules: arclm.datasets. 

from arclm.datasets import load_dataset, validate_records, deduplicate

records = load_dataset([{"text": "Hello"}, {"text": "Hello"}, {"text": "World"}])
vr = validate_records(records, required_fields=["text"])
print(vr.valid_count)  # 3

out = deduplicate(records, return_result=True)
print(out.kept, out.removed)  # 2 1

Configuration: DatasetConfig(source, text_field, …). Limits: exact dedupe only (not fuzzy); streaming for large files. Related: training consumes tokenized data.

Tokenizers

What: word-level and SentencePiece tokenizers. Why: native ArcLM models need integer ids; subwords handle morphology better than pure word-level. Modules: arclm.tokenizers. 

from arclm.tokenizers import Tokenizer, SentencePieceTokenizer

tok = Tokenizer(max_vocab=64)
tok.build("arc lm trains tiny models on local text")
print(tok.encode_text("arc lm trains"), tok.get_vocab_size())

sp = SentencePieceTokenizer(model_type="bpe", vocab_size=200)
sp.build("your corpus ...")

Limits: no auto-lowercase; word tokenizer is for teaching and small corpora. Related: checkpoint tokenizer restore via arclm.training.tokenizer_from_checkpoint.

Record schemas (extended)

Beyond simple text dicts, arclm.schemas defines validated record types (text, prompt/completion, instruction, conversation) used by data quality and web layers.
