Platform and tooling

Command-line interface

Entry points: arclm and python -m arclm. Commands that do not need torch: version, info, doctor, config, data, runs, cache, security. Torch-backed: train, eval, generate, chat, typically run. Web: web-api (extra). 

arclm doctor
arclm train --data data.txt --device cpu
arclm generate --model models/m.pth --prompt "hello"
python -m arclm web-api

Experiment tracking

from arclm.tracking import create_run, set_reproducible_seed, list_runs
set_reproducible_seed(42)
# create_run(...); tracker.record_metric(...); list_runs("runs")

Local manifests + JSONL metrics. Private paths redacted. Compare runs with compare_runs.

Hyperparameter search

arclm.search is hyperparameter search (grid/random), not document/BM25 search. Built on tracking.

ArcLM Blocks

Trimmed editions generated from one source: core, training, finetuning, loading-inference, evaluation, agents-tools, security. Install from git subdirectory or local build. 

python tools/build_arclm_distributions.py build-all
python tools/build_arclm_distributions.py check-drift
pip install "git+https://github.com/Ahmad-Al-Dibo/ArcLM.git#subdirectory=distributions/core"

Web Studio

FastAPI backend (arclm.web) + Next.js frontend (web/). Local workspace JSON. Training endpoints need torch.

Examples suite and Lab

  • examples/ — numbered folders 00–12; run_examples.py run-verified (CPU, no network).
  • lab/ — 32 progressive challenges (beginner → expert) via python -m lab.runner.

Releases

Version in src/arclm/_version.py. PyPI: arclm. CI: light matrix (no torch) + torch unit jobs on Python 3.9–3.14. Publishing: trusted publishing workflow or twine.
