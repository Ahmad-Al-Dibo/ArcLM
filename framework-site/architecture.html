Architecture

ArcLM is a single installable package (arclm) composed of domain subpackages. There is no separate microservice runtime. The optional-torch boundary is the most important structural rule.

Layer diagram (implementation-aligned)

Green: torch-free. Blue: requires [train]. Orange: optional third-party or generated artifacts. Dashed: lazy import boundary.

Root package

src/arclm/__init__.py exposes ~230 names via _EXPORTS + module __getattr__. First attribute access imports only that submodule. __init__.pyi mirrors the map for type checkers.

Web layer

src/arclm/web/ provides create_app(WebConfig) (FastAPI). Workspace state is JSON on disk. Studio training/eval coordinators import torch. Frontend: separate Next.js app in web/ talking to the API.

Blocks generator

tools/build_arclm_distributions.py walks import graphs from manifest roots, fails on excluded required imports, copies reachable modules, and writes inventories. Manifests: distributions/manifests/.

Where to change what

  • New public name → package __init__ + root _EXPORTS + __init__.pyi
  • New CLI command → cli.py parser + handler (lazy heavy imports)
  • New Block → manifest + builder
  • Never hand-edit distributions/<id>/src/**

Boundaries not to bypass

  • Do not import arclm.web from core packages.
  • Do not module-level import torch in light packages.
  • Do not import arclm.security package root from light packages (use submodules).
  • Do not skip require_torch at heavy package entry.
