## A. Project overview

ArcLM is a Python toolkit for language-model **data workflows, tokenizers, optional PyTorch training, Hugging Face inference, agents, and security**.

| Aspect | Detail |
|---|---|
| Language | Python 3.9â€“3.14 |
| Package name | `arclm` (PyPI) â€” **not** `arclm` vs `arcllm` confusion; canonical is **`arclm`** |
| Version | `src/arclm/_version.py` â†’ `__version__ = "2.0.0"` |
| License | Apache-2.0 |
| Build | setuptools, src-layout (`package-dir = {"" = "src"}`) |
| Heavy dep | **PyTorch optional** via extra `train` |

### Primary entry points

| Entry | Path | Notes |
|---|---|---|
| Console script | `arclm.cli:main` | `pyproject.toml` `[project.scripts]` |
| Module | `python -m arclm` | `src/arclm/__main__.py` â†’ `cli.main` |

1. **Core (no torch):** `import arclm` â†’ `configs` / `datasets` / `tokenizers` / `security` / `agents` / `tracking` / `search` / `logics` / `exceptions`.

## F. Architecture and data flow

### Layers (conceptual â†’ code)

| Layer | Packages | Rule |
|---|---|---|
| Lab | High-level `train_model`, `load_dataset`, CLI | Prefer for teaching examples |
| Developer | `Trainer`, `Config`, web, agents, checkpoints | Application code |
| Research | Native model internals, tracking, search, inspection | Extension / experiments |

There are **no** three separately named runtime layers in code â€” domain packages implement the roles.

### Optional-torch boundary

```text
import arclm
  â†’ __init__ lazy map only
  â†’ sys.modules does NOT contain torch

from arclm.tokenizers import Tokenizer
  â†’ still no torch

from arclm.models import ArcLM
  â†’ models/__init__ calls require_torch()
  â†’ OptionalDependencyError if torch missing
  â†’ else import torch + model code
```

**Rule:** Light packages (`configs`, `datasets`, `tokenizers`, `security`, `agents`, `tracking`, `search`, `logics`, `exceptions`, `registry`, `utils`, `cli` for doctor/security) must never module-level `import torch`.

### Training data flow

```text
text file / records
  â†’ datasets.load_dataset / prepare_data
  â†’ tokenizer.build / encode
  â†’ DataLoader (torch) or token lists
  â†’ Trainer.train_dataset / train_model
  â†’ loss, callbacks, tracking.record_*
  â†’ atomic_save_checkpoint / Trainer.save
  â†’ checkpoints.safe_load_* for resume
  â†’ Evaluator.evaluate (optional)
```

### HF inference data flow

```text
load_any_model(source, trust_remote_code=False)
  â†’ ExternalModelConfig / model load
  â†’ ExternalLoadedModel
  â†’ predict/generate â†’ HF generate or native path
  â†’ chat(messages) â†’ apply_chat_template if present
    else simple role:content fallback
```

### Agent data flow

```text
user intent
  â†’ Agent / AgentRunner
  â†’ model adapter (LLM or fake)
  â†’ tool calls (JSON schema from type hints)
  â†’ permission / side-effect checks
  â†’ tool.invoke
  â†’ results appended; loop until final or max steps
  â†’ trace (optionally redacted)
```

### Error propagation

- Domain errors â†’ `ArcLMError` subclasses.
- Missing extras â†’ `OptionalDependencyError` with `pip install "arclm[â€¦]"` hint.
- Do not swallow `OptionalDependencyError` in library code.

### Allowed dependency direction (verified design)

```text
exceptions, utils, registry, configs  â† depended on by almost everything
tokenizers, datasets, security        â† core peers; may use configs/exceptions
agents                                â† may use security (precise imports)
```

**Do not** import `arclm.web` from core packages. **Do not** import heavy `arclm.security` package root from light packages (import submodules like `security.configuration` instead â€” see agents).

## G. How to add a new feature

### G1. New torch-free utility API

1. Choose the domain package (e.g. `datasets`, `security`) â€” not a new flat root file unless truly cross-cutting.
2. Implement pure functions/classes; raise domain errors from `arclm.exceptions`.
3. Export from package `__init__.py` (`__all__`).
4. If it should be on `arclm.X`, add one line to `_EXPORTS` in `src/arclm/__init__.py` and regenerate `__init__.pyi` to match (see `tests/public_api`).
5. Add unit tests under `tests/unit/<area>/`.
6. Add an example under `examples/` if user-facing; register in `examples/manifest.json` if part of verified suite.
7. Document in `framework-site/reference/modules/<area>.html` and `docs/guide.md`.
8. Run: `pytest tests/unit tests/public_api -q` and light-import suite.

### G2. New torch-backed training API

1. Put it in the correct package (`training`, `models`, `inference`, â€¦).
2. Gate with `require_torch("feature name")` **before** `import torch`.
3. Do not import torch modules from light packages.
4. Tests: `tests/unit/...` (CPU) + optional smoke in `tests/smoke/`.
5. Update light-import test lists only if you accidentally made a light package heavy.

### G3. New CLI subcommand

### Existing rules (verified)

| Rule | Evidence |

| Recommendation | Why |
